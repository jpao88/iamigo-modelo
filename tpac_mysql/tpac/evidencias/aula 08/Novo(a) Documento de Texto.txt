Como el token dura 60 minutos, conviene hacerlas todas seguidas, empezando por un login nuevo. Te sugiero estos nombres para que queden ordenadas:

1. Login válido → aula08_01_login_valido.png
POST /auth/login con {"nome": "Login Teste", "senha": "segredo123"}. En la captura debe verse el 200 y la respuesta.

2. Login inválido → aula08_02_login_invalido.png
Lo mismo con "senha": "errada". Debe verse el 401 "Nome ou senha inválidos."

3. Token sin contraseña → aula08_03_token_sem_senha.png
Puede ser la misma respuesta del punto 1, siempre que se vea que tiene access_token y no tiene senha ni senha_hash. Para reforzarla, puedes sumar:

el SELECT en Workbench: SELECT nome, senha_hash FROM usuarios WHERE nome = 'Login Teste';, donde se ve el hash pbkdf2_sha256$... en lugar de segredo123;
o el payload decodificado con python -c "import jwt; ...", que muestra solo sub, nome, iat y exp.

4. Sin token → aula08_04_sem_token_401.png
Authorize → Logout, y luego GET /usuarios/6/tarefas. Debe verse el 401 "Token de acesso ausente."

5. Con token → aula08_05_com_token_200.png
Authorize con el token del punto 1, y luego GET /usuarios/6/tarefas. Debe verse el 200 con las tareas y, si entra en la captura, la línea Authorization: Bearer ... del Curl.

6. Regresión → aula08_06_regressao.png
